# RooPyth_GS — шаблон десктопного приложения для трейдинга

Краткая и актуальная инструкция по настройке и запуску проекта RooPyth_GS с поддержкой оркестрации Roo Code.

## Быстрый старт

1) Открой проект в VS Code.
2) Убедись, что в корне есть файл `.env` с `KODIKROUTER_API_KEY` (и `GITHUB_TOKEN`, если нужен push).
3) Активируй Roo Code в боковой панели VS Code и переключи режим на `orchestrator`.
4) Дай команду оркестратору:

```
/mode orchestrator
/task Запусти полный цикл разработки для десктопного приложения трейдинга
```

Оркестратор выполнит автоматизированные шаги: инициализация окружения, параллельную разработку модулей, тесты, аудит и push в GitHub.

## Проверка KodikRouter и моделей

Показать доступные модели (dry-run):

```powershell
cd 'c:\Projects_Roo\Versions\RooPyth_GS'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\get-kodikrouter-models.ps1
```

Автоматическое обновление `.roomodes`:

```powershell
.\scripts\get-kodikrouter-models.ps1 -UpdateRoomodes
# или с интерактивным выбором для каждого агента
.\scripts\get-kodikrouter-models.ps1 -UpdateRoomodes -Interactive
```

Если при вызове скрипта видны ошибки про `KODIKROUTER_API_KEY not set` — проверь файл `.env`.

## Как агенты работают с зависимостями

Агенты могут устанавливать Python-библиотеки в проектном окружении **только** при наличии явной инструкции (обычно это обязанность `deepseek-architect`). Рекомендуемый рабочий процесс:

1. Агент проверяет наличие библиотеки в `requirements.txt` и в окружении:

```powershell
pip list | Select-String library_name
```

2. Если пакет отсутствует и действительно нужен, агент выполняет установку в `.venv`:

```powershell
.venv\Scripts\activate
pip install library_name
```

3. Агент обновляет `requirements.txt`:

```powershell
pip freeze > requirements.txt
```

4. Агент логирует установку в `logs/cycle.log`:

```powershell
echo [%date% %time%] Установлена зависимость: library_name >> logs\cycle.log
```

Важно: агенты НЕ должны устанавливать системные пакеты (apt, brew, choco) или VS Code расширения без разрешения пользователя.

## Частые проблемы и решения

- `KODIKROUTER_API_KEY not set` — убедись, что `.env` в корне и правильный ключ.
- `ModuleNotFoundError` — активируй `.venv` и установи зависимости `pip install -r requirements.txt`.
- Проблемы с версиями пакетов — согласуй версии в `requirements.txt` и повтори установку.

## < ШТАТНЫЙ РЕЖИМ >

В штатном режиме при создании нового проекта достаточно:

Скопировать шаблон ANOTHER_proj в новую папку.

Прописать API-ключ в .env.

Открыть проект в VS Code, активировать Roo Code (режим orchestrator).

Дать команду: «Запусти полный цикл разработки» (или просто «Выполни план из .clinerules»).

После этого оркестратор автоматически:

Переключится на deepseek-architect.

Тот проверит Python, создаст .venv, requirements.txt (базовый), установит зависимости.

Затем параллельно запустит разработку бэкенда и фронтенда.

Далее аудит, GitHub push и уведомление.

Все проверки и установки выполняются без ручных тестов. Тестовые промпты из README.md нужны только для:

Отладки на этапе настройки шаблона.

Уверенности, что конкретный агент работает корректно.

Обучения нового пользователя.

 Но в боевом сценарии вы просто даёте задачу оркестратору, и он сам делает всё необходимое, начиная с проверки окружения.

##  🔧 Расширения Roo Code: Автономный "Мозг" Вашей Системы
Сама по себе среда Roo Code обладает высокой степенью автономности в рамках файловой системы вашего проекта.

Создание и редактирование файлов: Агенты могут не только модифицировать существующий код, но и создавать новые файлы и папки с нуля. Если для выполнения задачи требуется новый конфигурационный файл или папка для модуля, агент должен его создать.

Реакция на ошибки: Одна из мощных функций Roo Code — способность в некоторой степени "лечить" себя. Агент может видеть ошибки, возникающие при сборке или работе кода (например, ошибку компиляции или выполнения скрипта) и автоматически пытаться их исправить. Например, если он запускает main.py, а там не хватает импорта, он должен сам найти и добавить его.

Однако, есть и границы автономности. Roo Code действует в рамках пользовательской сессии и не обладает полной свободой. Он не может самовольно выполнить установку глобального расширения для VS Code без вашего подтверждения.

## 🧠 Логика Агентов (DeepSeek, Qwen, Kimi): "Мозги" Принимают Решения
Здесь ситуация еще интереснее. У вас настроены разные агенты для разных ролей (архитектор, дизайнер), и их поведение будет немного отличаться.

Архитектор (DeepSeek) должен быть наиболее подготовлен к решению инфраструктурных задач. Его логика построена так, чтобы сначала убедиться, что среда готова. При обнаружении отсутствия requirements.txt он не просто упадет, а начнет действовать по плану: создать и заполнить его, установить зависимости и т.д. Это именно то, что вы закладывали в расширенном промпте. Он должен сам принимать решения о том, чего не хватает для работы.

Дизайнер (Qwen) и Аудитор (Kimi) более узкоспециализированы. Их "кругозор" в большей степени ограничен их зоной ответственности. Qwen может создать папку styles/ для CSS-файлов, если её нет, но вряд ли будет проверять наличие Python.

Таким образом, за проактивность в создании необходимых файлов в основном отвечает архитектор (DeepSeek) и сама среда Roo Code.

⚖️ Практические рамки: Что Агенты Могут, А Что Требует Вашего Вмешательства?
Для наглядности я собрал это в небольшую таблицу.

Действие	Способность Агента (Roo Code & DeepSeek)
Создание/редактирование файлов и папок (.py, .js, src/, tests/)	✅ Да. Агенты могут создавать и редактировать файлы по мере необходимости.

Добавление/обновление кода и зависимостей (в рамках requirements.txt)	✅ Да. Это базовая функция, заложенная в архитектора.

Обнаружение и исправление ошибок (SyntaxError, ImportError)	✅ Да. Roo Code видит ошибки в терминале и может пытаться их исправить.

Установка глобальных расширений VS Code (например, новый линтер)	❌ Нет (без вашего разрешения). Это нарушило бы безопасность. Roo Code может предложить установить их, но решение остается за вами.

Модификация базовой конфигурации Roo Code (файл .roomodes)	❌ Нет. Эти служебные файлы, как и .gitignore, трогать не стоит.

Скачивание внешних бинарных зависимостей (например, компилятор C++)	❌ Нет. Установка системных пакетов — это задача DevOps, но агент может дать вам инструкцию.

Ключевой вывод: В рамках вашего проекта ваша команда AI-агентов достаточно автономна, чтобы создать всю необходимую файловую структуру и код для его работы. Но когда дело доходит до "глобальных" изменений (установка расширений VS Code, системных библиотек), финальное слово остается за вами.
