# DEVELOPMENT CHECKLIST

Цель: перевести шаблон RooPyth_GS из состояния "готов к разработке" в реальный рабочий проект.

## 1. Подготовка окружения
- [ ] Убедиться, что в корне есть `.env` с `KODIKROUTER_API_KEY`.
- [ ] Активировать виртуальное окружение:
  - Windows: `.venv\Scripts\activate`
  - Unix: `source .venv/bin/activate`
- [ ] Установить зависимости:
  - `pip install --upgrade pip`
  - `pip install -r requirements.txt`
- [ ] Проверить базовую работу Python:
  - `python -c "import requests, pytest; print('OK')"`

## 2. Проверка конфигурации проекта
- [ ] Убедиться, что `.roomodes` содержит нужные роли и инструкции.
- [ ] Оценить структуру директорий: `src/`, `tests/`, `logs/`.
- [ ] Проверить `.gitignore` и убедиться, что в репозиторий не попадают `.env`, `.venv`, `logs/`.

## 3. Запуск оркестратора
- [ ] Переключиться на режим `orchestrator` в Roo Code.
- [ ] Запустить основную задачу оркестрации:
  - `/mode orchestrator`
  - `/task Запусти полный цикл разработки для десктопного приложения трейдинга`
- [ ] Проверить, что оркестратор:
  - создал структуру проекта,
  - инициализировал `.venv`,
  - сформировал `requirements.txt`,
  - начал работу нужных агентов.

## 4. Создание базовой рабочей логики
- [ ] Убедиться, что созданы файлы:
  - `src/main.py`
  - `src/utils/config.py`
  - `src/utils/logger.py`
  - `src/integrations/binance.py`
  - `src/strategies/gamma_scalping.py`
  - `src/backtests/backtest_engine.py`
  - `src/ui/main_window.py`
- [ ] Проверить, что модули импортируются корректно.
- [ ] Убедиться, что бизнес-логика отделена от UI.

## 5. Написание и запуск тестов
- [ ] Создать `tests/` и базовые файлы:
  - `tests/test_models.py`
  - `tests/test_strategies.py`
  - `tests/test_backtests.py`
  - `tests/test_integrations.py`
- [ ] Запустить `pytest tests/ -v`.
- [ ] Исправить найденные ошибки.

## 6. Проверка интеграции и безопасности
- [ ] Убедиться, что API-ключи читаются из `.env`, а не захардкожены.
- [ ] Прогнать интеграционный тест UI ↔ backend.
- [ ] Запустить аудит:
  - `kimi-auditor` проверка безопасности,
  - `kimi-auditor` проверка модульности.

## 7. Упаковка и деплой
- [ ] Создать `build.py` и/или `requirements-build.txt`.
- [ ] Запустить PyInstaller для тестовой сборки.
- [ ] Проверить, что бинарный файл запускается.

## 8. Git и репозиторий
- [ ] Убедиться, что проект синхронизирован с GitHub.
- [ ] Проверить, что в `README.md` описан актуальный процесс запуска.
- [ ] Сделать коммит с рабочим состоянием и push в `origin/main`.

## 9. Примечания для разработки
- [ ] Партионно запускать агентов: не держать 10 задач одновременно.
- [ ] Использовать `.venv` для всех установок пакетов.
- [ ] Логировать ключевые события в `logs/cycle.log`.
- [ ] Не давать агентам менять `.roomodes` без явной необходимости.
